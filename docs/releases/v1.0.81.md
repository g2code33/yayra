# Yayra v1.0.81 — Office recovery, PowerPoint fidelity, and persistent Google handoff

Released: 2026-10-23

## Legacy Microsoft Office files

- Added first-class local viewing for Word 97–2003 (`.doc`) and PowerPoint
  97–2003 (`.ppt`) plus explicit binary Excel (`.xls`) routing.
- DOC/PPT parsing runs on a disposable copy in a bounded, short-lived module
  Worker and creates an in-memory, macro-free OOXML viewing copy. The selected
  source is never replaced, uploaded, or transferred away as Yayra's only copy.
- Existing Word/PowerPoint controls remain available where the recovered
  content supports them: search, zoom, tables, thumbnails, notes, print,
  slideshow controls, and unchanged-original Download.
- Compound File Binary stream inspection distinguishes DOC, PPT, and XLS even
  when the extension or MIME type is misleading. Unknown/damaged containers
  fail closed to the honest original-file fallback.
- Linux Open With metadata, document registry routes, PWA precache, Electron
  packaging verification, vendor manifests, licenses, and reproducible fixtures
  now include the legacy engines and formats.

## PowerPoint fidelity and honest recovery

- PPTX pictures now try authored raster/SVG/EMF/WMF alternatives rather than
  stopping at one broken relationship. Broken `<img>` surfaces are retired and
  replaced by accessible diagnostics instead of browser broken-image glyphs.
- Added bundled, offline EMF/WMF/EMF+ to SVG conversion with capability checks,
  deterministic vendor hashes, Apache-2.0 license, and third-party notices.
- Added cached SmartArt drawing traversal (`dsp:spTree`), including pictures
  related from the cached drawing's own `.rels` part even when relationship IDs
  collide with slide IDs, plus a bounded selectable/searchable native diagram
  fallback when the cache is absent but diagram data survives.
- Unresolved relationships, missing media, malformed SmartArt, and
  unexplained empty results now produce visible slide-level fidelity
  diagnostics; Yayra no longer silently calls those cases successful.
- Recovered diagram text participates in find and thumbnails. Slide notes,
  presentation controls, embedded media, equations, tables, slide numbering,
  and original-byte Download remain on the native path.

## Persistent Chrome-to-Yayra Google identity

- Web/PWA now returns from Google's full-page OAuth callback, consumes the
  verified PKCE transaction once, saves the sanitized Google profile, and
  restores the initiating Yayra path. The visible Yayra account remains signed
  in across browser/PWA restarts.
- Capacitor uses the exact verified `com.yayra.app:/oauth2redirect` deep link,
  persists the same profile, and returns control to the app after the system
  browser ceremony.
- Electron retains the loopback callback, stores credentials only through
  encrypted main-process `safeStorage`, focuses the initiating Yayra window,
  and sends only the display profile over IPC.
- Chrome/Google cookies are deliberately not extracted or injected. Google
  blocks transferring those website sessions into embedded browsers; Yayra
  reflects verified app identity and uses scoped APIs for supported actions
  instead of pretending a cookie transfer occurred.

## Google Drive download recovery

- Native website engines preserve their own cookies and user agent, follow
  redirects/confirmation flows, correlate delayed failures, track native
  downloads, and add completed supported files to Documents.
- A trusted `drive.google.com/uc?export=download&id=...` failure card can now
  offer **Download through Drive API**. Consent is separate and requests only
  `drive.readonly`.
- Desktop keeps scoped Google credentials in the encrypted main process and
  performs metadata, refresh, export/download, size checks, and revocation
  there. Renderer IPC receives only bounded bytes and safe metadata.
- Web/PWA and mobile persist only a random 43-character Yayra capability. The
  Worker AES-GCM-encrypts Google credentials in KV, binds the capability to the
  exact origin, applies a 30-day TTL, refreshes server-side, exports Google
  Docs/Sheets/Slides to DOCX/XLSX/PPTX, and streams bounded bytes.
- Logout deletes the local capability and Worker KV record before best-effort
  provider revocation. Electron likewise clears its encrypted store before
  attempting Google revocation. A former capability returns 401 and a foreign
  origin cannot download or revoke it.
- Supported delegated downloads open through the normal document registry
  rather than becoming false site-failure pages.

## Deployment and security changes

- Added exact-origin, rate-limited Worker routes:
  `POST /auth/google/exchange`, `GET /api/drive/download`, and
  `POST /api/drive/session/revoke` (plus OPTIONS).
- Google access/refresh tokens never enter Web/PWA or Capacitor JavaScript and
  never cross Electron renderer IPC. Unknown fields, token-bearing callbacks,
  broad scopes, malformed PKCE/state, oversized requests/responses/files, and
  origin/session mismatch fail closed.
- `docs/GOOGLE_SIGNIN.md`, `docs/CLOUDFLARE.md`, and
  `wrangler.worker.toml` document the OAuth client matrix, exact origins,
  `GOOGLE_DRIVE_SESSIONS` KV binding, independent
  `GOOGLE_DRIVE_SESSION_SECRET`, rotation behavior, revocation, and manual
  cross-platform verification.

## Packaging status and remaining limitations

- **PWA:** built and verified locally at version 1.0.81.
- **Linux:** packaging configuration verifies, but the sandbox's
  `electron-builder` could not complete the `.deb` build after its bounded
  retries. No `.deb` is claimed.
- **Windows/macOS/iOS/Android:** not packaged in this Linux sandbox. Android
  source contracts pass, but no Java/JDK or Android SDK is available for a
  Gradle compile; Apple and Windows toolchains are unavailable.
- **Live Google:** automated tests use isolated fakes. Real consent requires
  deployment-owned Google client IDs/secrets, configured callback URIs, a
  Cloudflare KV namespace/encryption secret, and a human browser/device pass.
  The Worker has not been deployed from this sandbox.
- **96-slide reference deck:** the original PPTX and WPS-exported PDF were not
  attached, so this release cannot honestly certify pixel-for-pixel parity on
  all 96 slides or claim that the reported slides 2 and 13 match WPS exactly.
  Synthetic/real-format fixtures cover the missing-cache SmartArt and broken
  metafile/image paths, and the runtime now surfaces any unresolved slide
  explicitly. Final acceptance still requires the two reference files and an
  all-slide comparison with a target of zero unexplained blanks and zero
  broken-media icons.
- Macros, transitions, animations, OLE objects, and linked-only media remain
  non-executable by design. Some charts or unusually damaged Office constructs
  may use an explicit static/explanatory fallback rather than Office-perfect
  rendering.
