# Yayra v1.0.76 — Google account return-to-Yayra connection

Released: 2026-10-21

## Google sign-in now returns to Yayra

- Typing or opening Google Account entry points no longer loads a native
  `ERR_FAILED` page and no longer opens a raw `ServiceLogin` page that can
  authenticate only the user's other browser.
- First-party Google Account, Manage Account, and interactive login routes now
  start Yayra's provider-compliant Authorization Code + PKCE flow in the
  system browser. Its verified callback returns the sanitized Google profile,
  updates the Yayra account/avatar state, and focuses the initiating Yayra
  window automatically, including detached/profile windows.
- Gmail and other Google products that redirect to first-party ServiceLogin
  keep their original Yayra tab URL and history. After connection, the tab
  offers a safe continuation to the product's credential-free HTTPS origin.
- The connection surface is live and tab-scoped: it shows waiting, error,
  retry, connected, switch-account, continuation, and back actions without
  reopening OAuth during ordinary chrome renders.

## PowerPoint projector and toolbar polish

- Slideshow mode now keeps automatic/unresolved PowerPoint text tied to the
  authored slide, shape, or table-cell surface. Tables no longer inherit the
  projector chrome's white foreground and disappear on light slides.
- Automatic text gets contrast-aware black/white fallbacks for light and dark
  slide or cell fills, while explicit OOXML run colours remain untouched.
- Download, Present, and Print retain fully opaque, high-contrast labels on
  mouse hover, keyboard focus, and press; both real Present controls now use
  the intended clean primary-action styling.

## Provider and privacy guarantees

- Third-party Google OAuth URLs keep their original relying-party client ID
  and callback in the system browser; Yayra never replaces them with its own
  callback.
- Captured ServiceLogin URLs do not cross Electron renderer IPC or the
  Android native-to-JavaScript bridge; only provider/reason metadata returns.
- Product continuation accepts only sanitized HTTPS Google/YouTube origins;
  paths, queries, fragments, credentials, ports, auth hosts, and lookalike
  domains are rejected.
- Yayra receives the verified profile, not the system browser's cookies.
  Access, refresh, and ID tokens remain outside renderer code and URLs.
- Published desktop workflows now fail closed when the required Google OAuth
  client configuration is absent, preventing another release with a visible
  sign-in control that cannot complete.

## Platforms and regression coverage

- Electron desktop, Android/iOS Capacitor, Web, and installed PWA adapters use
  the same account-connection contract; Web/PWA persists its current tab
  snapshot before the required full-page provider redirect.
- Regression coverage pins account-root navigation, Gmail ServiceLogin
  redirects, callback focus/state updates, OAuth/client separation, sanitized
  product continuation, render deduplication, and Android native routing.
