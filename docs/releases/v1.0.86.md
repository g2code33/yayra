# Yayra v1.0.86 — Local image actions, AI handoff, and Google app coverage

## Fixes

- Wired image/link and **Ask Yayra AI** actions from native context menus on
  Yayra's own document pages back into the active browser shell. Back, Forward
  and Reload now target the active tab (with the menu state reflecting its tab
  history). Previously, these actions were built with a no-op callback or used
  the shell WebContents history instead of the active tab.
- Opening a copied `blob:`, image `data:`, or local image `file:` address now
  opens Yayra's safe local-image viewer instead of treating the address as a
  Google search. The viewer accepts images only; it does not navigate to
  arbitrary data or local HTML files. Renderer-owned blob URLs remain temporary
  and may expire when their source page is closed or the app restarts.
- Deferred AI auto-asks until the AI page has completed its initial render,
  preventing a nested render from leaving a blank-looking tab.
- Added Google app-launcher products visible in the supplied screenshots
  (Chrome, Blogger, Saved, Arts & Culture, Merchant Center) to the Google
  Services hub. On desktop they use the same Yayra-dedicated Chrome profile,
  so Google website sign-in is shared with Gmail and Drive. Only products with
  a supported, consented read-only API provide in-Yayra data previews; other
  products open their real Google websites.
- Updated service-tile labels to distinguish read-only previews from signed-in
  website launches.
