# Yayra v1.0.70 — full-window Google sign-in and always-live pages

Released: 2026-10-21

> **Superseded for authentication by v1.0.74.** This page records the behavior
> shipped in 1.0.70; do not use its app-controlled `BrowserWindow` design as
> current security guidance. Version 1.0.74 moved Google OAuth and interactive
> sign-in to the OS external user-agent and removed `googleAuthWindow.cjs`.

## Fixed

- Google account authentication on Electron now opens in a real, top-level Yayra `BrowserWindow`, with Google occupying the complete native window instead of appearing inside the embedded website surface or being delegated to an unrelated external browser.
- The OAuth completion redirect stays in Yayra. After the provider callback settles, Yayra safely resumes the originating tab and restores focus instead of leaving the user stranded in Chrome/Firefox or requiring an unexplained manual return.
- Google OAuth started by a website uses the exact Chromium `Session` of that Yayra profile. Cookies, storage, callback state, and the resulting website login therefore remain associated with the correct source tab/profile.
- Direct OAuth navigations, top-level redirects, and provider popups all use the same full-window path. Closing the auth window preserves the source tab and clears the live loading state.
- One-time callback URLs are not blindly replayed into the source tab. Yayra waits for callback navigation to settle and reloads the original relying page if an authorization code is still visible; provider scripts that close their callback window are still recognized as completed.
- Yayra app identity and arbitrary website identity are deliberately separate: Settings → Account uses a dedicated persistent Google-auth session, while a website uses its originating browsing profile.
- App-level cancellation is immediate and explicit. Closing the window aborts the loopback wait and reports `sign_in_cancelled` instead of waiting for the normal OAuth timeout.
- Google account management and account switching now use the same trusted top-level Yayra surface. Apple and Microsoft retain their existing external-browser routing.
- Fixed the persistent frozen/static page shown after submitting from an open search-suggestion list—most visible as a Google results header with a blank body until Refresh. Navigation now retires the dropdown, cancels pending suggestion work, and restores the live native surface before replacing the omnibox.
- Late autocomplete responses are render-scoped and cannot re-hide a newly loaded page after their old input has detached. Render teardown and native `loading-stop` also reconcile stale snapshot state as independent recovery layers.

## Security preserved

- Authorization Code + PKCE, cryptographic state verification, exact loopback callback acceptance, minimal `openid email profile` scopes, and encrypted token storage remain unchanged.
- Auth windows have Node integration disabled, context isolation and sandboxing enabled, top-level navigation constrained to HTTP(S), and provider popups contained in the same surface.
- App-account cookies use the dedicated persistent `persist:yayra-google-auth` partition; website auth never crosses profiles.

## Architecture and regression coverage

- Adds `electron/googleAuthWindow.cjs`, a dependency-injected auth-window manager inspired by RX Store's sound full-window behavior but adapted for Yayra's floating shell, profile isolation, callback correlation, and source-tab restoration.
- Adds deterministic coverage for app and website Sessions, callback settlement, code replay protection, popup containment, cancellation, timeout cleanup, source-tab destruction, and focus restoration.
- Adds exact regressions for navigating while suggestions obscure the native view, a late response from a detached omnibox, and a zero-bounds native surface at page-load completion.
- Updates the OAuth, auth bridge, native webview bridge, BrowserShell, architecture documentation, and manual live-provider checklist for the new behavior.
