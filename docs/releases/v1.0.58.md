# Yayra v1.0.58 — GitHub passkey completion on Linux

## Fixed

- Fixes GitHub passkey registration ending in `NotAllowedError` after Yayra accepted the **Confirm passkey** action.
- Holds the site's untouched `navigator.credentials.create()` / explicit `get()` call before Chromium enters virtual CTAP. Yayra now completes PolicyKit verification, arms user verification and presence, restores the requesting view's focus, and only then starts the native WebAuthn operation.
- Defers a selected conditional-passkey account callback until the same verified-presence gate is ready.
- Cancels held ceremonies cleanly on navigation, abort, or exact-page system-browser handoff.
- Stops offering a misleading second confirmation if a released ceremony does not finish; users are directed to retry the site request or use the system browser.
- Restores the white Google **+** menu by isolating its semantic sections from legacy page-card CSS, while keeping recent-tab selection, image/file actions, Create images, and Canvas intact.
- Removes the oversized native URL tooltip from recent-tab rows without removing their accessible URL labels.
- Fixes the installed desktop PDF reader startup on Linux by serving bundled `.mjs` files with a deterministic JavaScript MIME type under `yayra://` instead of relying on OS file associations.
- Adds a desktop smoke parse through the packaged PDF.js engine and module worker, plus build/precache checks for both lazy PDF assets.

## Security and privacy

- Release commands are authenticated with a random per-document capability generated in the isolated preload. Page JavaScript cannot self-approve a passkey ceremony.
- Challenge bytes, user handles, credential IDs, attestation, authenticator data, signatures, and the release capability never enter Yayra's UI renderer.
- Old or unavailable request gates fail closed to the system-browser path instead of trying a late virtual touch.
- GitHub `collector.github.com/github/collect` connection failures remain classified as non-causal telemetry failures.

## Compatibility note

Opening DevTools displaces Electron's single CDP session used by the Linux local provider. Yayra detects that loss and fails closed to **Use system browser** rather than reporting local-provider success.
