# Yayra v1.0.69 — Firefox-parity website backdrops and text contrast

Released: 2026-10-20

## Fixed

- Fixed the remaining case where a website still appeared as a white page in Yayra while the same page rendered dark and readable in Firefox.
- Cloudinary HEIC/HEIF source extensions are now removed after choosing WebP or JPEG; the raw extension could otherwise override automatic format negotiation and return an image this Electron build could not decode.
- Media recovery now starts in the page main world at document start, before React/Vue `onError` handlers can remove a failed full-screen background image.
- A first safe JPEG retry survives framework error handling; if it also fails, Yayra retires the broken-image glyph and uses the website's own declared `theme-color` for the backdrop.
- Full-screen failed images are treated as decorative by geometry even if older site markup supplied alt text, while meaningful ordinary images continue to retain their accessible alt fallback.
- Added a conservative low-contrast invariant: when a site explicitly declares a dark theme but exposes white text over an unintended white full-page fallback, Yayra repairs the full-page background—including the actual React root child—without changing the site's writing or content.
- Same-origin dynamic `/api/` and GraphQL reads now send `Cache-Control: no-cache` and `Pragma: no-cache`, so restored tabs cannot keep an older site configuration (for example, an obsolete white background or missing question) from Yayra's persistent profile cache while Firefox fetches the current published configuration. Cross-origin APIs are untouched to avoid introducing CORS preflights.
- The recovery rechecks after asynchronous app rendering and DOM replacement, covering websites that fetch their configuration after `dom-ready`.

## Regression coverage

- Added assertions that HEIC/HEIF suffixes cannot override WebP/JPEG delivery.
- Added a simulated white-on-white React page proving its nested full-page child is restored to the site-declared dark theme while all text remains untouched.
- Added document-start preload coverage proving a framework cannot unmount the compatibility retry before it runs.
- Preserved existing browser, passkey, autofill, profile, native-view, and accessibility behavior.
