# Yayra v1.0.66 — Reliable Yayra-authorized website passkeys

## Fixed

- Fixes GitHub website-passkey authentication remaining indefinitely at **Completing passkey** while the site waits for browser interaction.
- Keeps virtual authenticator user presence and verification armed until the page's real WebAuthn promise settles. A `credentialAsserted` / `credentialAdded` CDP event no longer clears presence early and races Chromium's final response.
- Adds a bounded main-process completion watchdog and an internal abort signal. A released native ceremony that stalls is actively canceled, its provider state is cleared, and the UI reports a timeout with retry/system-browser recovery.
- Checks the active profile's encrypted website-credential vault for the requested RP before advertising local authentication. A missing credential now fails fast to the exact-page system-browser path instead of entering an unfulfillable local request.
- Restores focus to both the Yayra window and requesting site view before releasing the held native WebAuthn call.

## Yayra verification gate

- Website passkeys can now use the configured Yayra account verifier—6-digit PIN, Touch ID, or system lock—to authorize the separate RP-scoped website credential.
- A successful verification mints a cryptographically random, 30-second, single-use main-process grant bound to the shell WebContents, profile, tab, request ID, RP ID, and create/get action. Mismatched and replayed grants fail closed.
- Users without a configured Yayra verifier can create a 6-digit Yayra PIN directly from the website-passkey flow, avoiding repeated Linux system-password prompts. PolicyKit remains an explicit fallback.
- The Yayra account credential authorizes release only; it is never substituted for or presented as the website's origin-bound credential.

## Account selection and status

- Preserves discoverable-account selection: conditional requests wait for verification, while explicit requests reuse verification already completed before account discovery and do not prompt twice.
- Updates the omnibox live through **Use Yayra passkey**, **Verify with Yayra**, **Completing with Yayra**, success, retry, cancellation, timeout, or system-browser handoff.
- Keeps all website private keys encrypted, profile-scoped, and outside renderer IPC. Challenges, user handles, credential IDs, authenticator data, and signatures remain outside Yayra chrome.
