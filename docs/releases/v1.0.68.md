# Yayra v1.0.68 — Reliable website media rendering

Released: 2026-10-20

## Fixed

- Fixed Cloudinary-backed website images and full-screen backgrounds that could render in Firefox but fail inside Yayra when the system Firefox and Electron/Chromium codec sets selected different representations.
- Cloudinary `f_auto` images are now requested as broadly supported WebP before cache lookup; raw HEIC/HEIF deliveries are transcoded by Cloudinary instead of being handed to an unsupported local decoder.
- Added an automatic JPEG retry for the rare machine where the WebP delivery still cannot decode.
- Removed Chromium's small broken-image “sad face” from failed decorative images while preserving meaningful image alt text for accessibility.
- A failed full-viewport decorative backdrop now falls back to the website's own declared `theme-color`, preventing an unintended white page with invisible light text.
- Applied the same compatibility path to ordinary Yayra tabs, floating/secondary browser windows, and installed website-app windows.
- Compatibility redirects use a distinct URL, naturally bypassing a stale undecodable media cache without deleting cookies, saved sessions, site storage, or unrelated cached content.

## Regression coverage

- Added URL transformation tests for `f_auto`, raw HEIC/HEIF, existing explicit formats, signed Cloudinary URLs, video URLs, and unrelated hosts.
- Added session-listener tests proving installation is exactly once and only image resources are rewritten.
- Added a browser-script simulation covering JPEG retry, broken-decoration retirement, and website-owned theme-color fallback.
