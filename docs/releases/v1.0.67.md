# Yayra v1.0.67 — Self-healing desktop top chrome

## Fixed

- Fixes the desktop-only split freeze where websites continued working while the complete top row—tabs, tab close buttons, New Tab, window drag handle, and minimize/maximize/close—stopped accepting input.
- Treats every renderer pointer capture as a revocable lease. Re-render, focus loss, visibility changes, legacy `mouseup`, native drag termination, shell teardown, an inactivity watchdog, or a main-process recovery signal now releases tab/window gestures and their IPC state synchronously.
- Delays pointer capture until a tab or window-handle press actually crosses its drag threshold. Ordinary tab selection and title-handle double-clicks no longer enter pointer capture at all.
- Retires body-mounted tab menus and their outside-click scrims as one lifecycle-owned pair. Outside `pointerdown`, blur, re-render, a 30-second safety deadline, or invariant repair removes both, so an invisible orphan cannot cover only the renderer-owned chrome while a native website surface remains interactive.
- Keeps lightweight menu scrims and tab context menus physically below the 36 px top row. Clicking a tab or caption control closes lightweight dropdown state and continues to the intended control in the same gesture.
- Adds guarded Electron native popup menus: one popup per window, exact-once cleanup on blur/hide/minimize/close/renderer loss, plus an independent safety deadline for a lost OS menu-close event.
- Closes an expanded floating radial overlay whenever a Yayra shell regains native focus, preventing a transparent always-on-top window from intercepting the browser chrome.
- Enforces native website-view bounds in the main process so a stale resize report can never place a `WebContentsView` over the tab/caption row.

## Preserved behavior

- Tab selection, close, middle-click close, context menus, pointer reordering, horizontal tab scrolling, New Tab, window movement, double-click maximize/restore, and all caption controls remain available.
- The entire top strip and every descendant remain renderer-owned `no-drag` hit targets; no Electron CSS drag region is reintroduced.
- Active websites and background tabs remain live—input repair never refreshes or restarts the page.

## Regression coverage

- Covers lost pointer-up, delayed capture, re-render during reorder, native focus recovery IPC, orphan and paired menu scrims, caption controls after recovery, native menu timeout/blur cleanup, native page-bound clipping, and main-process window-drag cancellation.
