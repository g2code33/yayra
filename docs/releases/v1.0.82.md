# Yayra v1.0.82 — complete local-file recovery and browser reliability

Yayra 1.0.82 makes local documents first-class recovery items. A session can now
restore websites together with every supported local-file tab—PDF, PowerPoint,
legacy Office, Word, spreadsheets, images, text, and the safe unknown-file
fallback—without serializing filesystem paths.

## Local-file recovery

- Rolling crash/quit recovery now records local-file tabs as well as HTTP(S)
  tabs.
- **Keep all tabs & files**, **Just close**, the persistent restore bar, the
  new-tab Continue card, and Ctrl+Shift+T all understand document recovery.
- Tab order, title, tab-group metadata, and stable group membership are retained.
- Private file tabs never receive a persistent recovery id and never enter a
  session snapshot.
- The old five-item recovery truncation is removed from Restore all. The card
  remains compact, while the action restores the complete sanitized snapshot.

### Desktop

Electron stores source paths only in its trusted main-process document catalog.
Renderer/session data receives an opaque `local-*` capability. On recovery, the
main process resolves that capability, rechecks the source and size limit, and
returns bytes—not a path. Moved or unavailable sources stay visible in a
recovery tab with **Try again** and **Locate file…**.

### Web, PWA, and mobile picker files

Picker files have no reusable filesystem path after restart. Yayra therefore
copies their unchanged source bytes to a profile-scoped, origin-private
IndexedDB record under a random `docrec-*` capability. Recovery loads that exact
copy. Quota denial, unavailable IndexedDB, user-cleared site storage, or browser
eviction is reported immediately; the tab remains visible with **Choose file
again…** instead of disappearing.

Pending recovery writes are allowed to settle before a native Yayra window
closes (with a bounded timeout). Every record enforces the same 300 MiB per-file
limit as the document workspace.

## Security and privacy

- Recovery descriptors accept only validated opaque ids, basename-only names,
  bounded MIME/name fields, and bounded sizes.
- Arbitrary paths, credential-bearing URLs, malformed ids, private tabs, and
  raw runtime `yayra://doc/*` ids are rejected by profile storage.
- Close-session records are now keyed to the active Yayra profile.
- Browser/PWA/mobile bytes remain same-origin and profile-keyed; they are never
  uploaded by the recovery service.

## Reliability fixes included in this build

- Tab groups use a profile-scoped durable catalog and survive navigation,
  restart, session restoration, updates, and browsing-data clearing until the
  user explicitly removes or ungroups them.
- Clear Browsing Data preserves browser-chrome local storage while still
  clearing website partitions.
- Google OAuth completion is bound to the initiating profile and hydrates that
  profile from both live IPC completion and the authenticated invoke result.
- Printing discovers usable printers and falls back to save-as-PDF when none is
  available.
- Native overlay captures are full-resolution lossless PNGs. Their renderer
  cache is now LRU-bounded to three captures / roughly 48 MiB of encoded data
  and is cleared when the window is destroyed.
- Full-screen Yayra overlays no longer blur the underlying website.

## Validation coverage

Automated regressions cover:

- all registered document extensions plus the unknown-file fallback;
- exact-byte web/PWA/mobile recovery;
- opaque desktop-catalog recovery;
- missing-file Locate and reselect states;
- mixed website/PDF/PNG close-session ordering;
- private-file exclusion;
- group metadata retention;
- sanitized profile storage with no path leakage;
- complete restore beyond the five-row preview; and
- bounded, lossless native snapshot caching.

The normal typecheck, lint, version-lockstep, document/session suites, broad
nonphysical test suite, web/PWA build verification, update tests, packaging
layout checks, and static desktop smoke are run for the release.

## Honest limitations

- A desktop catalog capability follows the original source. If that source is
  deleted, moved, or becomes unreadable, Yayra needs the user to locate it.
- Browser/PWA/mobile recovery depends on origin-private storage quota and
  retention policy. If the browser clears or evicts the byte copy, Yayra keeps
  the tab and asks for the original file again.
- Local file bytes are capped at 300 MiB for the internal workspace.
- Private file tabs intentionally do not survive restart.
