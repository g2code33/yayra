# Yayra dictionary and vocabulary system — Phase 0 plan

## Phase 0 findings and release gate

- Internal pages, Settings navigation, and the floating-mini internal-page dispatcher are in `packages/shared-ui/src/components/BrowserShell.js`. The native text-selection toolbar is injected by `electron/webviewBridge.cjs`; the centralized CSP is `src/security/csp.js`.
- Existing profile storage is separate from the new browser's IndexedDB document-recovery database. Dictionary packs and personal vocabulary therefore have their own IndexedDB stores. Vocabulary records are profile-owned; pack installation/removal must never enumerate or delete them.
- The current native selection toolbar offers Copy, Search and Ask Yayra AI for text; editable fields additionally have Cut and Paste. Those actions and their regression tests must remain intact. Desktop hotkeys and selection capture are separate capabilities; an application hotkey cannot reliably read another app's selected text without an explicit copy/clipboard flow.
- No dictionary data was found in the current app. The candidate `wordnet-db@3.1.14` tarball has registry SHA-512 integrity `sha512-zVyFsvE+mq9MCmwXUWHIcpfbrHHClZWZiVOzKSxNJruIcFn2RbY55zkhiAMMxM8zCVSmtNiViq8FsAZSFpMYag==` and npm describes its payload as WordNet 3.1, but its bundled licence is headed “WordNet Release 3.0” and gives the 3.0 copyright notice. This mismatch is not authoritatively resolved. The pack was **not downloaded into Yayra, offered for installation, or redistributed**. The package-wrapper MIT label is not treated as the dictionary-data licence.
- No medical, pharmacy, or business dataset has been selected or verified. There are no bundled dictionary entries. Any claim that those categories already have content, or that the app gives clinical advice, would be false. A reviewed source and legal/attribution approval are a release blocker for preloaded packs.

## Short implementation plan

1. **Data and trust boundary:** add a versioned, explicit dictionary-pack import format; require source, dataset version, pack version, build/update dates, licence and attribution; validate every entry, cap untrusted input sizes, record an import-file SHA-256, and render all imported strings as text. Do not embed or fetch any unverified corpus. Keep remote lookup out of local search.
2. **Storage and pack lifecycle:** use separate IndexedDB stores for pack manifests/entries, resumable download checkpoints (for future verified pinned downloads), and profile-scoped vocabulary. Activate a new pack only after its entries are validated and written. Disabling/removing/updating pack records must not delete saved words, stars, highlights, notes, collections or history.
3. **Offline library:** implement normalized local search, prefix/inexact suggestions, category/source filters, duplicate/source grouping and side-by-side comparison. Include empty, unavailable-source, import, storage and error states and show per-result source/licence attribution.
4. **Personal vocabulary:** implement saved entries and selected text, favourites, highlights, notes, tags, collections, bounded search history, and JSON import/export. Explicit saves from a private source may be saved by user action; private searches are not written to history. Pack data is not exported as user vocabulary.
5. **Yayra integration:** route `yayra://dictionary` and `yayra://vocabulary` in both full and mini shells; add dictionary lookup and explicit Save Selection actions to the existing selection toolbar without removing Copy/Search/Ask AI/Cut/Paste. Add settings for destination and shortcut only where the native host can actually honour them.
6. **Verification:** add unit tests for parsing/validation, search and suggestions, profile isolation, pack lifecycle, import/export, checksum handling and selection-action compatibility; run targeted tests, the complete test suite and production build. Document platform gaps and any corpus/permission blockers rather than claiming unsupported behavior.

## Pack import format

A UTF-8 JSON file has `format: "yayra-dictionary-pack"`, `formatVersion: 1`, a `metadata` object with `id`, `title`, `category` (`general`, `medical`, `pharmacy`, `business`), `version`, `datasetVersion`, `packVersion`, `source`, optional HTTPS `sourceUrl`, exact `license`, `attribution`, `buildDate`, `updatedAt`, and `description`, plus an `entries` array. Each entry has a `term` and one or more definitions; definitions can include `partOfSpeech`, `examples`, `synonyms`, `antonyms` and `etymology`. Imported data is marked as user-supplied; metadata claims are not cryptographically vouched for by Yayra.

## Explicit limits

- The first-party pack catalogue remains unavailable until exact corpus provenance and redistribution rights are verified. User import supplies a usable offline library without inventing sample definitions. Resumable *network* downloads, signed manifests, and pack auto-updates are not enabled while there is no verified remote pack manifest.
- Desktop-wide selection capture is not claimed. The optional global shortcut requires the user to enable it, copy text first, then press the shortcut; clipboard text is read only on that explicit press and never overwritten/restored. Registration can fail due to OS/Wayland support or a shortcut conflict. Global shortcut behavior is desktop Electron only; Android and browser/PWA do not receive this system-wide capability.
- Desktop mini-window lookup reuses an existing mini and opens another tab rather than replacing its tabs. Private-source lookups never hand off into a persistent mini. An explicit Save Selection action may persist the selection to the chosen profile's personal vocabulary.

## Delivery status

- Implemented the offline IndexedDB store, normalized local search, category/source filtering, combined same-term results, two-entry comparison, source/licence attribution, safe `textContent` rendering, user JSON pack import with metadata validation/checksum, pack enable/remove, and separate profile-owned saved words, stars, highlights, notes, tags, collections, bounded history, and personal-vocabulary JSON import/export. Pack removal and version replacement leave that personal data untouched by design.
- Added both full-shell and mini-shell internal routes, Settings navigation, configurable lookup destinations, selected-text Dictionary / Save Selection actions, and a consent-gated desktop clipboard shortcut with two allowed accelerators. Existing Copy/Search/Ask AI/Cut/Paste behavior remains covered by tests.
- **No category currently has an included corpus.** Searches return a clear local-empty state until the user imports a pack. Clinical/medical content is neither provided nor presented as medical advice. The only package research candidate remains excluded pending authoritative resolution of its license/data-version discrepancy.
- Verification in this checkout: dictionary/selection tests pass; `npm run lint` passes; `npm run build:web --ignore-scripts` and `node scripts/verify-pwa.mjs` pass. The complete Node test run reported 1,223 passing and two unrelated Linux packaging failures: one packaging attempt could not complete `electron-builder` in this environment, and a source-pin test expects PPTX MIME registrations in the local `build/linux/yayra.desktop`. That desktop file was intentionally left untouched because it is one of the pre-existing local Linux files that differs from the latest remote tree. `npm run typecheck` passes.
